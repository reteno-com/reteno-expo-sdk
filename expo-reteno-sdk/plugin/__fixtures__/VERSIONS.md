# Fixture versions

Generated by `create-expo-app --template blank-typescript@sdk-<N>` (`--no-install`), then `npm install`, then pinning `expo` to the latest patch of that SDK (`npm install expo@~<N>.x.y`), then `npx expo prebuild --no-install --platform all` **without** expo-reteno-sdk or its config plugin. Blank templates only; `app.json` sets `name`/`slug` = `fixture`, `ios.bundleIdentifier` and `android.package` = `com.example.fixture`.

iOS project directory and target name: `ios/fixture/`, `ios/fixture.xcodeproj` (target `fixture`).
Android package: `com.example.fixture` (`android/app/src/main/java/com/example/fixture/`).

Host: macOS (Darwin 25.5.0), Node v24.12.0, npm 11.6.2. Node satisfies the SDK 58 requirement (>= 22.13).

## Source of Android values

- `minSdk`, `compileSdk`, `targetSdk`, `buildTools`, `ndkVersion`, `agp`, `kotlin`: `node_modules/react-native/gradle/libs.versions.toml`. This is the `expoLibs` version catalog that `expoAutolinking.useExpoVersionCatalog()` (android/settings.gradle) loads. It is read through `expo-modules-autolinking/android/expo-gradle-plugin/expo-autolinking-settings-plugin/.../ExpoAutolinkingSettingsExtension.kt`.
- No `android.*SdkVersion` / `android.kotlinVersion` overrides exist in any fixture's `android/gradle.properties`, so catalog values apply.
- Fallbacks (only if the catalog is missing): `ExpoRootProjectPlugin.kt` defaults (minSdk 24, compileSdk 35, targetSdk 35, buildTools 35.0.0, ndk 27.1.12297006, kotlin 2.0.21).
- Gradle wrapper: `android/gradle/wrapper/gradle-wrapper.properties`.
- Root build files are Groovy in all variants (`android/build.gradle`, `android/app/build.gradle`).
- JVM toolchain for KSP/Kotlin modules: 17 (`ExpoModulesCorePlugin.gradle`, `applyKspJvmToolchain`).
- iOS deployment target: `ios/Podfile` fallback (`podfile_properties['ios.deploymentTarget'] || ...`) and `IPHONEOS_DEPLOYMENT_TARGET` in `ios/fixture.xcodeproj/project.pbxproj` (identical in all variants).
- iOS app target `SWIFT_VERSION`: from `project.pbxproj` (app target = 5.0 in every variant). Pod-level Swift version comes from each podspec, not the app target.
- Expo package versions: `node_modules/<pkg>/package.json` after install.
